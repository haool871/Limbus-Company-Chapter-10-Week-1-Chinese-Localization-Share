## 3. 输出契约

译稿是紧凑 JSON，键是工作包里的 `[序号]`，值是 `[译文, 依据]`：

```json
{
  "0": ["按下按钮，视野随即明亮起来。", "直译韩文；与上一句衔接，无语义增删"],
  "16": ["1F 泉", "地点名；零协 MainUIText 已确立 샘터=泉，层号用 3층→3F 惯例"]
}
```

- **必须为分到的每个序号给出条目**，包括"照抄零协候选"的（依据写清为何适用）。
- `expected` 旧值不要手写，由 `merge_edits.py` 从批次当前文件读取。
- 依据要具体：引用上下文依据、零协出处、或新拟专名的理由。不得只写"已翻译"。

## 6. 质量清单（逐条自检）

1. **回应关系**：韩文以 `그리고/하지만/그럼/역시/도` 开头或含 `-잖아/-지/-네` 时，这句依赖前文，译文要让依赖可见，不能译成首发问句。
2. **比喻不压成判断**：`-처럼/마치/같다` 要保留"像/如同"。
3. **反讽与语气**：`-는가/-나/-지` 结尾是反问，用反问句；`하하/흠/후우` 按语境判嗤笑还是真笑。
4. **称呼一致**：同一场景内同一人的译名、称呼前后一致；韩文没有的敬称不要补。
5. **半句跨条**：一条被拆成两条时，中文保持断句呼应，不各自补全成完整句。
6. **不吞信息、不加戏**：不省略称呼与语气词，也不添加原文没有的比喻或情绪。
7. **人物口吻**：查 `style/角色/<角色>.md`；机制句式查 `style/机制句式模板.md`；UI 查 `style/UI与系统文本.md`；旁白查 `style/叙事与旁白.md`。

### 9.1 序号错位自查（上一轮出现过，务必执行）

- 特别检查分块的首条与末条：首条要用 `--from` 指定的序号，末条要用 `--to` 指定的序号。
