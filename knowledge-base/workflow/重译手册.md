# 剧情重译手册（带上下文标准）

> 本文件是「按上下文重译」的执行规范。**每次重译一个文件前必须先读本手册。**
> 背景：早期翻译按 `id` 逐条独立翻译，导致回应关系、比喻、反讽、指代、称呼变化全部丢失。
> 本手册固化修正后的标准，并用 `S1002B` 作标杆样例。

---

## 0. 一句话标准

**翻译单位是「对话回合（exchange）」，不是「一条记录」。**
一句话该怎么说，取决于它**在回应什么**、**谁接着说**。

---

## 0.5 ⚠️ `ctx_dump` 的 `posN` **不等于** `id` —— 按 pos 写回会毁数据

`StoryData` 里存在 **`id: null` 的记录**（韩/英源本身就无 id），位置从此错开：

| 文件 | 错开位置 |
| --- | --- |
| `S1004B` | `pos217` 起错开 1（`pos217`→`id218`） |
| `S1005B` | `pos158/159`、`pos162/163` 各错开 1 |

`ctx_dump.py` 输出的 `--- posN id=…` **同时打印了 pos 与 id**，但两者并排容易看混。
**若把 dump 里的 `posN` 当成 `id` 写回，会改错记录。**

- 实例：`S1005B` dump 的「pos44」实际是 `id44`（以实玛利「……！」）、
  「pos82」实际是 `id82`（鸿璐「……」）——按 pos 写回会直接毁掉这两条台词。
- **规则**：写回一律**按真实 `id` 定位**；`posN` 只用于定位到上下文，不作键。
- 写回脚本应先断言 **`id == 期望值`**，不符即中止。

## 2. 五类必查问题（S1002B 实战教训）

### 2.1 回应关系被切断（最严重）

原译常把「回应」翻成「首发问句」，读者以为角色第一次说这件事。

| id | 官方英文 | 错误 | 正确 |
| --- | --- | --- | --- |
| 8 | `And now you know how I feel listening to your endless questions.` | 这和你那些没完没了的问题，是同一个水平的提问 | ……这跟你那些没完没了的问题，**是同一个水平**。懂了吗，你们？ |
| 41 | `And this is supposed to answer the question of who you are?` | 所以……你到底是什么人？ | 所以……**这就算回答了我问的你是谁**？ |
| 95 | `You people got rid of her, nice and clean!` | 把她干净利落地解决掉了吗？ | （承接 94 的「不过，说到底……你们不也……」）**把她干净利落地解决掉了吗？** |

**判据**：若英文以 `And / But / So / Then / That's / ...` 开头，或含 `too / either / still`，
说明这句**依赖前文**；译文必须让这层依赖可见。

### 2.2 比喻/类比被压成判断句

| id | 官方英文 | 错误 | 正确 |
| --- | --- | --- | --- |
| 8 | `... And now you know how I feel listening to your endless questions.` | 是同一个水平的提问 | 用「和你那些问题**是同一个水平**」保留类比 |

**判据**：英文的 `like / as if / no different from / same as` 是**明喻**，不能译成「是……」的判断。

### 2.3 反讽与语气层次

- 韩文 `-는가 / -나 / -지` 结尾表示反问或确认，中文要用**反问句**，不要译成陈述。
- `Fie` 不在所有语境都译「怎会」；`Hah`／`Hmph` 要看是**嗤笑**还是**真笑**。
- 例：`So you've been consumed too, senpai…` → 「结果，连你也被吞噬了吗……」保留了「结果」这层因果推进。

### 2.4 指代与呼称一致性

- 同一人在同一场景内的译名、称呼必须**前后一致**（`西西弗百货` 不要一会儿「百货店」）。
- 敬称按 `style/角色/*.md` 与 SOP §5.8；`young X` / KR `X 군` **丢掉不译**（见 SOP §5.9）。
- 但丁旁白是**第一人称**：英文有 `I / my / me` 时中文必须出现「我」。

### 2.5 半句跨条

连续两条本来是**一句话被拆成两条**（韩文/英文都如此）：

- id=37 `한때 여기는 이런 곳이었어.` + id=38 `바닥을 쳐야만 다시 일어설 수 있는 곳.`
  → 「这里曾经是那样的地方。」+「要想重新站起来，就得先跌到最底层的地方。」
- 处理：中文也保持**断句呼应**，不要各自补全成完整句。

## 4. 硬性红线（违反会破坏美术/功能）

1. **`<color=…></color>`、`<size=…>`、`<style=…>`、`<mark=…>`、`{0}` 占位符逐字符不变。**
   `<i>`／`<b>`／`<u>`／`<s>` 可删（零协保留率仅 17%）。
2. **引擎方括号标记**（`[Vibration]`、`[OnSucceedAttack]`、`[ChargeNoirAlly]` 等拉丁标识符）原样不译；
   **显示方括号**（`[鸿璐]`、`[第8赛季]`）要译。
3. **但丁内心独白 `<...>` 保留尖括号**。
4. **只改 `content`，不动 `id` / `model` / `teller` / `title` / `place`**。
5. **不要对 JSON 做文本级正则清洗**（会删换行、留孤立标签）——逐字段精确赋值。

## 7. RPGSystem（探索模式）对话的上下文单位

RPGSystem 的对话**天然成组**，结构是：

```json
{"key": "D1090", "texts": [
   {"index": 0, "text": "...", "speaker": "以实玛利"},
   {"index": 1, "text": "...", "speaker": "罗佳"}
]}
```

**翻译单位就是 `texts` 这一组**（1155 组 / 约 3,262 条文本），不是单条 `text`。
同组内的对话彼此紧密相关（一问一答、连续吐槽），必须整组一起读、一起译。

文件清单（按体量）：

| 文件 | 条数 |
| --- | ---: |
| `rpg-loc-dialogue-floor-1.json` | 671 |
| `rpg-loc-dialogue-floor-3.json` | 660 |
| `rpg-loc-dialogue-floor-4.json` | 598 |
| `rpg-loc-dialogue-floor-b1.json` | 454 |
| `rpg-loc-dialogue-floor-b2.json` | 436 |
| `rpg-loc-dialogue-floor-2.json` | 222 |
| `rpg-loc-dialogue-common-a1c10p1.json` | 174 |
| 其余（npc / quest / narration / 小文件） | 约 47 |

**RPG 特有的注意点**：

1. **`speaker` 是显示名，必须本地化**（`Ishmael`→以实玛利）。但 `Le Noir`、`L'Inamovible`
   这类**有意保留的拉丁专名**不要译；`???` 保持不揭示。
2. **行尾 `——` 多为「被打断」，不是漏字**。`in detai—` → 「细——」是**正确的**官方处理方式
   （英文原文就是断的），不要「补全」成「细节」。
   判据：对照英文源是否同样以 `—`／`-` 截断。
3. **组内跨条的完整句**：同一人连说数条、或一条句子的后半在下一人的条目里（如
   `D1091#2`「有什么巨大的东西……」＋`#3`「……从上方坠落了下来。」），中文保持断句呼应。
4. **`text` 里的 `<i>` 可删**；`<color>`/`<size>`/`<style>`/`{0}` 必须逐字符保留。
5. `patch_v2/RPGSystem/*.json` 与 `Lang/LLC_zh-CN/RPGSystem/` 同名，英文源在
   `Localize/en/RPGSystem/EN_*.json`，**key 一一对应**（比 StoryData 的 id 对齐更稳）。
