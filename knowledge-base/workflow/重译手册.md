# 剧情重译手册（带上下文）

仅适用于当前批次明确允许编辑的字段。历史全文与例句保存在上一轮归档；当前工程流程见 [版本更新流程](版本更新流程.md)。没有活动批次时不开始重译。

## 0. 翻译单位与定位

翻译单位是对话回合或 RPG 的一组 `texts`，不是孤立一条记录。先读全文，明确谁在回应谁、句子是否跨条、称呼是否随情境变化。

### 0.5 位置与 id

`pos` 不等于 `id`。重复/空 id 不能用字典归并，也不能假定同 id 语义相同。上下文工具按各语言原始顺序保留全部记录，遇到不能唯一对应的条目人工核对。写回使用 `batch.json` 给出的完整路径、期望旧值与原文快照，不把上下文编号当作键。

### 0.6 源语言

按批次记录的实际源文翻译，优先韩文。官方英文可能改写、丢掉敬称或自行补充性别与比喻；英文只作参考。没有韩文时才使用已记录的 EN/JP 来源，不能把缺失来源包装成“按韩文审校”。

### 0.6b 语义、文风与上游边界

文风与术语参考当前适用的零协证据，语义以当前官方源文为准。

- 未变源文对应的有效零协字段受保护，不在本次补译中润色。
- 变更源文对应的旧译必须复核，非空不代表有效；按本批次明确范围翻译或确认新版上游。
- 零协原有语义疑点另列审计清单，不再要求“补回所有上游信息”同时又“所有上游字句不变”。

## 1. 执行

先用 `ctx_dump.py` 或 `rpg_dump.py` 导出本批次上下文；语义审校与文风润色分别完成后，用 `batch apply` 的显式编辑清单写回。每条修改附原文依据、期望旧值和审校状态。标签、占位符及不可编辑字段受工具保护；不用正则清洗 JSON。

`id/key/index/model` 不作为译文。已核实的 RPG 结构 `texts[].speaker` 是显示名（例如 `단테 / Dante / 但丁`），工具按显示文本处理；顶层 `speaker` 默认仍视为结构标识。其他陌生结构需先核实字段用途，不能把整个同名字段全局替换。

场景自称、敬语、术语和品牌名均查当前版本例句；不要用历史改动数量衡量这一轮是否完成。

## 2. 五类必查问题（S1002B 实战教训）

### 2.1 回应关系被切断（最严重）

原译常把「回应」翻成「首发问句」，读者以为角色第一次说这件事。

| id | 官方英文 | 错误 | 正确 |
| --- | --- | --- | --- |
| 8 | `And now you know how I feel listening to your endless questions.` | 这和你那些没完没了的问题，是同一个水平的提问 | ……这跟你那些没完没了的问题，**是同一个水平**。懂了吗，你们？ |
| 41 | `And this is supposed to answer the question of who you are?` | 所以……你到底是什么人？ | 所以……**这就算回答了我问的你是谁**？ |
| 95 | `You people got rid of her, nice and clean!` | 把她干净利落地解决掉了吗？ | （承接 94 的「不过，说到底……你们不也……」）**把她干净利落地解决掉了吗？** |

**判据**：若英文以 `And / But / So / Then / That's / ...` 开头，或含 `too / either / still`，
说明这句**依赖前文**；译文必须让这层依赖可见。

### 2.2 比喻/类比被压成判断句

| id | 官方英文 | 错误 | 正确 |
| --- | --- | --- | --- |
| 8 | `... And now you know how I feel listening to your endless questions.` | 是同一个水平的提问 | 用「和你那些问题**是同一个水平**」保留类比 |

**判据**：英文的 `like / as if / no different from / same as` 是**明喻**，不能译成「是……」的判断。

### 2.3 反讽与语气层次

- 韩文 `-는가 / -나 / -지` 结尾表示反问或确认，中文要用**反问句**，不要译成陈述。
- `Fie` 不在所有语境都译「怎会」；`Hah`／`Hmph` 要看是**嗤笑**还是**真笑**。
- 例：`So you've been consumed too, senpai…` → 「结果，连你也被吞噬了吗……」保留了「结果」这层因果推进。

### 2.4 指代与呼称一致性

- 同一人在同一场景内的译名、称呼必须**前后一致**（`西西弗百货` 不要一会儿「百货店」）。
- 敬称按 `style/角色/*.md` 并回查当前零协例句；`young X` / KR `X 군` 的历史习惯是省去小称，不可据英文补出尊称。
- 但丁旁白需核对韩文的人称；英文有 `I / my / me` 不足以要求中文机械补“我”，也不要漏掉韩文明确的人称关系。

### 2.5 半句跨条

连续两条本来是**一句话被拆成两条**（韩文/英文都如此）：

- id=37 `한때 여기는 이런 곳이었어.` + id=38 `바닥을 쳐야만 다시 일어설 수 있는 곳.`
  → 「这里曾经是那样的地方。」+「要想重新站起来，就得先跌到最底层的地方。」
- 处理：中文也保持**断句呼应**，不要各自补全成完整句。

## 3. 标记与验收

引擎方括号、占位符和富文本标签保持完整且嵌套有效；不因历史零协删过某个斜体标签，就擅自删除本批次原文标签。显示方括号例外写入批次决策。`<I think …>` 等但丁独白是正文，不是斜体标签。

初译后先核对语义，再按 [通读润色手册](通读润色手册.md) 检查流畅度。完成后运行 `python3 tools/batch.py verify`；检查通过只证明机械条件及审校记录完整，不能代替实际通读。

RPG 中保持组内问答与跨条呼应。被打断的句尾不要凭空补全，是否保留截断应依据实际源文。译名采用当前零协证据，例如“黑派”“红派”，不沿用已作废的保留拉丁原文结论。
