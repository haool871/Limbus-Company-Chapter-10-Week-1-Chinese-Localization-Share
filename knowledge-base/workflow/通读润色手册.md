## 0. 判定标准：什么才算「翻译不好」

**只改这三类，不要按个人偏好重写。**

### 类别 A：跟英文不跟韩文，中文被撑长

韩文简短，英文加了很多修饰，中文照英文写 → 句子变长、变绕。

| 文件#id | 韩文（短） | 英文（长） | 错误中译 | 正确 |
| --- | --- | --- | --- | --- |
| `S1005B#66` | 내게 변명한들, 사실이 달라지진 않지（找借口也没用） | 用"更柔和的线来绣这份记录"的比喻 | 若用更柔和的线来绣这份记录能让你好受些，就请便吧。但事情的真实，是不会因我的同情而改变的。 | 找借口也没用。事实不会因为我的同情而改变。 |

### 类别 B：漏掉原文信息

| 文件#id | 韩文 | 错误中译 | 正确 |
| --- | --- | --- | --- |
| `S1005B#62` | 너희를 도와야 우리도 원하는 걸 얻을 수가 있거든（**得帮你们，我们才能**得到想要的） | 只是恰好，为你们提供助力，能让我们的目标更容易达成 | 只是得帮你们一把，我们才能得到自己想要的东西。 |

### 类别 C：生硬句式（欧式中文）

**注意**：`对于`／`所…的`／`正因如此` 这些**零协自己也在用**（`对于` 239 次、`所…的` 3169 次），
是这个体裁的正常文风。**不要一概磨平**。只有下列情况才算毛病：

1. **一个句子里套了三层以上「的」**：
   - ✗ 判处被告的永久驱逐刑**的**条件中，存在一定程度的宽容性
   - ✓ 对被告判处永久驱逐刑时，条件是留有一定通融余地的
2. **动宾被拆成「名词＋存在/进行/予以」**：
   - ✗ ……**予以**确认。
   - ✓ ……辩护方表示知悉。
3. **`对于` + 长定语开句**（中文习惯把话题前置后立刻给主语）：
   - ✗ 那一瞬间，**对于**自己曾相信是最好的每一个行动……
   - ✓ 那一刻，我曾以为是最好的每一个选择……
4. **`被…所…`／`作为…的…` 连用**：
   - ✗ 作为象征界的存在，她作为外力很难与罪人发生互动
   - ✓ 她身为象征界的存在，又属于外力，很难与罪人发生互动

## 1. 绝对不要做的事

- ✗ **不要因为「读着不够文雅」就改**——角色口吻（堂吉诃德古语、良秀极简、李箱书面）是刻意的。
- ✗ **不要磨平零协本就在用的句式**（见上）。
- ✗ **不要改语义正确且通顺的句子**——第二轮只做「减法与理顺」，不做偏好性改写。
- ✗ **不要动批次清单之外的字段**。`key/id/index/model` 等结构标识受保护；显示用标题、称呼、RPG `texts[].speaker` 仅按已确认的字段用途和本轮范围处理。
- ✗ **不要动机制/UI 文件**（`Bufs`/`Passives`/`Skills_*`/`BattleKeywords`/`*UI*`/`MainUIText` 等），
  那是书面术语体，生硬是正常的。

## 2. 工序

```bash
cd /home/shb/文档/汉化/_kb

# ① 导出带上下文的全文（StoryData 用 ctx_dump，RPG 用 rpg_dump）
python3 tools/ctx_dump.py StoryData/S10XX.json --out /tmp/p_S10XX.txt
python3 tools/rpg_dump.py RPGSystem/rpg-loc-dialogue-floor-1.json --out /tmp/p_f1.txt

# ② 通读全文，把「读起来别扭」的句子逐条记下来（KR/EN/CN 三语都在眼前）

# ③ 只改有把握的；每条改前先问：韩文支持我这么改吗？改完会不会丢信息？

# ④ 校验
python3 tools/batch.py verify
```

## 3. 交付要求

汇报时**每条给出**：文件#id、韩文、原译、新译、属于 A/B/C 哪一类、为什么。
若某句「读着别扭但说不出哪里错」，**不要改**，单独列出来给人工判断。

**改动宜少不宜多**：这一轮的目标是「把明显不顺的理顺」，不是重写。
改动数量由实证问题决定，不设“每文件必须改几条”的指标。用 `batch apply` 写回并更新与当前译文绑定的审校记录。
