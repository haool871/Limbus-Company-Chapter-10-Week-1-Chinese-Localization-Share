# 更新与排障

常规操作以 [版本更新流程](版本更新流程.md) 为唯一入口；旧七步“先合并旧补丁”流程已退役。

| 现象 | 处理 |
| --- | --- |
| 当前没有 `patch_v2/` | 正常；上一轮已归档。运行 `batch status` 查看是否存在新批次，不恢复旧目录 |
| 验收提示无活动批次 | 等待阶段验收不适用；游戏更新并审核范围后才能建立批次 |
| 原文看似未新增但技能数字变了 | 对新旧快照运行 `scope --new ...`；工具比较内容而非数量 |
| 英文多出标题而韩文没有 | 看报告的 `language_differences`，核对引擎结构，不直接判成剧情漏译 |
| 重复/空 id、组内 index 变化 | 查看完整上下文，记录 `alignment_reviewed` / `structure_reviewed`，使用完整路径编辑 |
| 零协有中文但源文改了 | `upstream_review`：核对新源之后才采用，非空不代表适用 |
| 编辑提示旧值不匹配 | 重新读当前批次字段与历史事务；不要跳过断言强写 |
| 中断事务或需要撤销 | `batch rollback --transaction <事务号>`；完整字节备份，按逆序回滚 |
| 源快照或模板校验失败 | 停止该批次，保留证据；不要修改哈希来绕过错误。重新核对快照/批次来源 |
| 语义筛子无疑点 | 不代表无错；对着实际源文和上下文复核 |
| 标签检查失败而源文本身特殊 | 回查源文件，明确显示方括号例外；不要全局忽略引擎标签或改原文 |

游戏加载问题与翻译流程验收是两类检查。仅在执行安装任务时检查：游戏构建是否仍匹配目标快照、完整零协包和字体是否安装、语言配置是否正确、本批次文件哈希是否与交付清单一致。JSON 合法不等于游戏一定能加载。

安装前保留实际将被替换文件的原始副本及清单。若加载失败，先恢复这些文件；不要删除整个 Lang 目录，也不要用“只复制旧补丁”假装能移除本次新文件。进一步定位时，在可恢复的安装副本上按文件分组缩小范围。

发布只使用已验证的交付目录；保留历史包，提交前查看仓库差异并只暂存本次明确文件。工具不会自动安装、提交或推送。
