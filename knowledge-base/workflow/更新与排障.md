### 0.9b ✅ 已做：补丁已与零协新版逐值对齐（字段级合并）

零协 `2026092102` 把补丁里 109 个文件的内容**重译**了一遍。如果补丁继续用旧译覆盖，
用户装完补丁看到的反而比**只用零协更旧**。因此本版做了一次**字段级合并**：

**裁决规则（用户明确定下，下次照此执行）**
> 零协有译文的一律采用零协；零协为空、零协缺记录处保留我们的。

**结果**

| 项 | 数字 |
| --- | --- |
| 采用零协译文 | **7082 处**（字符串 + 嵌套 `texts`/`steps`/`levelList` 内），涉及 109 个文件 |
| 零协留空、保留我们的 | 1639 处 |
| 补丁独有、零协没有的记录 | 46 条 / 9 个文件（**必须保留**） |
| 合并后与零协的残余差异 | **0 处**（逐条逐值比对） |

**工具**：`tools/merge_zeroasso.py`
```
python3 tools/merge_zeroasso.py --dry-run   # 先看会改多少
python3 tools/merge_zeroasso.py             # 正式合并（报告可回滚）
python3 tools/merge_zeroasso.py --revert    # 从报告回滚
```

**⚠️ 合并的三个坑（都踩过）**
1. **必须递归进 `texts` / `steps` / `levelList`**。RPG 分组记录的正文是
   `texts: [{index, speaker, text}]` 这样的**对象数组**，只合并顶层字符串字段会
   漏掉全部对话（第一次就漏了 973 条）。`coinlist`/`coindescs` 更深一层，同理。
2. **`id: null` 的记录会全部落进同一个键桶**（`S1004B`/`S1005B` 就有，见 `重译手册 §0.5`）。
   桶内对齐必须用**整表下标**，不能拿整表下标直接去索引桶内列表，否则错位到别的记录。
3. **非字符串字段（`id`/`key`/`index`/`level`/`place`）一律以补丁为准**，
   合并绝不能改动它们——那是定位键，动一条就会串整段对话。

**每次零协更新后都应该重跑一次合并**，否则又会积出新的漂移。

### 语料重建的正确顺序（⚠️ 必须先删索引缓存）

```
cd _kb
rm -f data/_file_index.json          # ← 关键！不删会漏掉整块新内容
python3 tools/pm_lib.py build         # 重建 {逻辑名: {lang: 路径}} 索引
python3 tools/export_corpus.py        # 重导 corpus.jsonl
rm -f data/_align.pkl
python3 tools/align_index.py build    # 重建对齐索引
python3 tools/extract_confirmed_pairs.py
python3 tools/audit_glossary.py --stats --save
python3 tools/clean_glossary.py
```

**实战踩坑（2026-09-21）**：`data/_file_index.json` 是**缓存**，它按 `逻辑名 → {lang: 实际路径}`
映射。换基础包后若不删它，会出现**某个语言整块缺失**：

- 症状：重建后 `cn` 比 `kr`/`en`/`jp` 少约 9,000 行（正常应约等或 cn 略多）。
- 根因：旧索引里 `StoryData/S1002B.json` 只有 `{en, jp, kr}`、**没有 `cn`**，
  于是 `iter_corpus` 对这个文件**完全不产出中文**——整个 Canto 10 的中文都没进语料。
- 排查手法：
  ```
  # ① 看某文件在索引里有没有 cn
  python3 -c "import json;d=json.load(open('data/_file_index.json',encoding='utf-8'));print(d.get('StoryData/S1002B.json'))"
  # ② 看语料里各语言行数是否均衡
  python3 -c "
  import json,collections
  c=collections.Counter()
  for line in open('data/corpus.jsonl',encoding='utf-8'): c[json.loads(line)['l']]+=1
  print(dict(c))"
  ```
- **教训**：**换基础包后重建语料，第一步永远是删 `_file_index.json`。**

### 另一个坑：多行文本会破坏 TSV（2026-09-21）

`extract_confirmed_pairs.py` 生成的 `confirmed_pairs.tsv` 是**制表符分隔的单行结构**。
但英文/中文文本**可能含真换行**（`
`），若不转义，一条配对会横跨多行，直接破坏表结构。

- **症状**：工具报「确认配对 1866」，但文件有 **2119 行**，其中 **207 行不含制表符**，
  内容是 `Extraction`、`싱글레어`、`9월 23일` 这类**碎片**。
- **后果**：任何按行解析该文件的脚本都会拿到垃圾行；用 `awk`/`cut` 取的列会错位。
- **修法**：入库前转义换行——
  ```python
  e = e.replace("\r\n", "\\n").replace("\n", "\\n")
  c = c.replace("\r\n", "\\n").replace("\n", "\\n")
  ```
- **自查**（以后生成任何 TSV 都要跑）：
  ```
  # 行数应与工具自报的条数一致；且不应有无制表符的行
  wc -l < terms/confirmed_pairs.tsv
  grep -vc $'\t' terms/confirmed_pairs.tsv    # 只应有 1 行（表头前的注释行）
  ```

重建后的规模（零协 `2026092102` 基准）：

| corpus.jsonl | 658,583 行 / 99.8 MB（cn 164,980 / kr 164,635 / en 164,497 / jp 164,471） |

## 2. 闪退排障：按这个顺序查（从最可能到最不可能）

### 2.1 先拿日志
Limbus 是 Unity 游戏。日志位置按平台：

| 平台 | 路径 |
| --- | --- |
| Windows | `%USERPROFILE%\AppData\LocalLow\ProjectMoon\LimbusCompany\Player.log` |
| Linux/Proton | `~/.steam/steam/steamapps/compatdata/<AppID>/pfx/drive_c/users/steamuser/AppData/LocalLow/ProjectMoon/LimbusCompany/Player.log` |
| 原生 Linux | `~/.config/unity3d/ProjectMoon/LimbusCompany/Player.log` |

**本次实战：这三处都没有日志**，说明崩溃发生在 Unity 初始化早期（还没开始写日志）。
这种情况直接跳到 2.3。

### 2.2 有日志时
搜 `Exception` / `Error` / `CustomLocalization` / `Json` / `Deserialize`，日志通常直接点名文件。

### 2.3 无日志时，按「结构性」从高到低查

| 优先级 | 检查项 | 命令/方法 | 本次结果 |
| --- | --- | --- | --- |
| ① | `config.json` 是否指向存在的语言目录 | `cat Lang/config.json`，确认 `LLC_zh-CN` 目录在 | ✅ 正常 |
| ② | 游戏侧 129 文件 JSON 是否可解析 | 见 §1 第 4 步 | ✅ 129/129 |
| ③ | 目录结构是否与基础包一致（**多出/少了目录**） | `diff <(cd $GAME && find . -type d\|sort) <(cd $BASE && find . -type d\|sort)` | ✅ 只多出预期的 `Font/`、`RPGSystem/` |
| ④ | 补丁文件是否全部就位 | 遍历比对 | ✅ 0 缺失 |
| ⑤ | 补入记录的**字段集合**是否与官方 en 一致 | 见 §4.2 | ✅ 0 异常 |
| ⑥ | 字体文件是否存在且非 0 字节 | `ls -la $GAME/Font/Context/ChineseFont.ttf` | ✅ 23.8 MB，md5 与来源一致 |
| ⑦ | 基础包版本是否匹配当前游戏 | `Info/version.json` vs 游戏版本 | ⚠ 本次未验证 |
| ⑧ | 备份/回滚到「上一次可用」版本 | 见 §3 二分定位 | — |

### 2.4 本次的结论与教训
- 上述 ①–⑥ 全部正常，**没能定位到具体原因**（用户自行解决）。
- **教训**：以后更新前先做 §1 第 6 步（留快照），并记录「上一次可用」的提交号，
  出问题时可以**二分**（见 §3），而不是事后盲查。
- **教训**：`pos`/`id`、JSON 合法性、字段类型都查过之后，剩下的可能性就是
  **基础包与游戏版本不匹配**或**某个文件的文本内容触发了游戏自己的解析器**
  （例如富文本标签、超长行、异常字符）。这两类只能靠二分定位。

## 3. 二分定位法（最可靠的排障手段）

前提：有「上一次可用」的提交号（记为 `GOOD`）与当前版本（`HEAD`）。

```bash
cd /home/shb/文档/汉化/Limbus-zh-CN-patch
git diff --name-only $GOOD HEAD -- patch/     # 变化的文件清单
```

**第一步：粗分。** 把变化的文件分成两半，只覆盖一半回游戏，测试。
- 崩 → 问题在这一半；不崩 → 在另一半。

**第二步：细分。** 对「崩的那一半」再二分，直到定位到单个文件。

**第三步：定位到文件后，再看该文件的 diff：**
```bash
git diff $GOOD HEAD -- patch/<文件>
```
重点看：**新的富文本标签**、**超长文本**、**异常字符**、**新增/删除了记录**。

> 本次没有任何文件被判定有结构性错误，所以若要继续排查，二分是唯一可行路径。

## 4. 手动核验脚本（工具不存在时用）

### 4.1 零协原文是否被改动（最关键的红线）
```bash
cd /home/shb/文档/汉化/_kb && python3 - <<'PY'
import json,os,sys
sys.path.insert(0,'tools')
from build_translation import walk_strings
BASE='../LimbusLocalize_latest/LimbusCompany_Data/Lang/LLC_zh-CN'; P='patch_v2'
tot=diff=0
for dp,dn,fn in os.walk(P):
    for f in fn:
        if not f.endswith('.json'): continue
        rel=os.path.relpath(os.path.join(dp,f),P); bp=os.path.join(BASE,rel)
        if not os.path.exists(bp): continue
        try:
            bb={str(r.get('id',r.get('key'))):r for r in json.load(open(bp,encoding='utf-8-sig')).get('dataList',[]) if isinstance(r,dict)}
            pp={str(r.get('id',r.get('key'))):r for r in json.load(open(os.path.join(dp,f),encoding='utf-8-sig')).get('dataList',[]) if isinstance(r,dict)}
        except Exception: continue
        for rid in pp:
            if rid not in bb: continue
            for path,pv in walk_strings(pp[rid]):
                bv=bb[rid].get(path)
                if isinstance(bv,str) and isinstance(pv,str):
                    tot+=1
                    if bv!=pv: diff+=1
print(f'共享字段 {tot} / 差异 {diff}  （差异必须为 0）')
PY
```

### 4.2 补入记录的字段集合是否与官方 en 一致
```bash
cd /home/shb/文档/汉化 && python3 - <<'PY'
import json,os
GAME='/home/shb/.local/share/Steam/steamapps/common/Limbus Company/LimbusCompany_Data/Lang/LLC_zh-CN'
BASE='LimbusLocalize_latest/LimbusCompany_Data/Lang/LLC_zh-CN'
OFF='/home/shb/.local/share/Steam/steamapps/common/Limbus Company/LimbusCompany_Data/Assets/Resources_moved/Localize/en'
def L(p):
    try: return json.load(open(p,encoding='utf-8-sig'))
    except Exception: return None
bad=0
for dp,dn,fn in os.walk('_kb/patch_v2'):
    for f in fn:
        if not f.endswith('.json'): continue
        rel=os.path.relpath(os.path.join(dp,f),'_kb/patch_v2')
        g=L(os.path.join(GAME,rel)); bp=os.path.join(BASE,rel)
        if not g or not os.path.exists(bp): continue
        b=L(bp)
        bids={str(r.get('id',r.get('key'))) for r in (b or {}).get('dataList') or [] if isinstance(r,dict)}
        d,f2=os.path.split(rel); o=L(os.path.join(OFF,d,'EN_'+f2))
        orows={str(r.get('id',r.get('key'))):r for r in (o or {}).get('dataList') or [] if isinstance(r,dict)}
        for r in g.get('dataList') or []:
            if not isinstance(r,dict): continue
            rid=str(r.get('id',r.get('key')))
            if rid in bids or rid not in orows: continue
            miss=set(orows[rid].keys())-set(r.keys()); extra=set(r.keys())-set(orows[rid].keys())
            if miss or extra:
                bad+=1
                if bad<=20: print(f'  [{rel} #{rid}] 缺 {sorted(miss)} 多 {sorted(extra)}')
print(f'补入记录字段异常: {bad}  （必须为 0）')
PY
```

## 6. 下一批新增翻译：开工清单

游戏出新章节时，按这个顺序做，不要跳步。

### 第 0 步：先体检（30 秒，能省几小时）
```
cd _kb
python3 tools/doctor.py
```
它会报：零协基准包版本、补丁 JSON 是否全部合法、补丁的文件分布、
游戏安装目录（config / 字体 / 补丁是否同步）、术语资产、语料缓存、
以及一句「能不能开工」的结论和下一步命令。

**只要 `doctor.py` 报错，先修它，不要往下走。** 环境不对时后面每一步都是白做。

### 第 1 步：先更新零协基础包（否则全是白做）
1. 从零协发布页下载最新汉化包
2. 备份旧基础包（`mv LimbusLocalize_latest LimbusLocalize_latest.old`）
3. 解包新基础包到 `LimbusLocalize_latest/`
4. 记录新版本号：`cat LimbusLocalize_latest/LimbusCompany_Data/Lang/LLC_zh-CN/Info/version.json`

**为什么要先做**：新增内容里有一部分零协已经翻过（本次就有 25 个覆盖文件）。
先更新基础包，才能算出「真正需要新译」的范围。

### 第 2 步：重建语料与对齐索引
```
cd _kb
python3 tools/pm_lib.py build                    # 刷新文件索引
python3 tools/export_corpus.py                   # 重导四语语料（约 106 MB）
python3 tools/align_index.py build               # 重建 (f,id,k) 对齐缓存
python3 tools/extract_confirmed_pairs.py         # 重抽实证配对
python3 tools/audit_glossary.py --stats --save   # 重跑术语审计
python3 tools/clean_glossary.py                  # 刷新清理后的术语表
```

### 第 3 步：算出新增范围（**用 `tools/scope.py`，不要再手写脚本**）

```
cd _kb
python3 tools/scope.py                 # 全量扫描，打印四类缺口 + 逐条漏译清单
python3 tools/scope.py --since         # 只看「游戏里有、零协包没有」的部分
python3 tools/scope.py --only StoryData --top 40
```

**不要假设新增内容还在上次那 129 个文件里。** 新增可能在 StoryData、RPGSystem、UI、道具、
语音、被动……任何位置。`scope.py` 以**官方 en 的文件列表**为权威，
逐个文件比对「en / kr / 零协 / 本补丁」，所以文件位置事先未知也能找出来。

**四类缺口**（报告里直接给类名）：

| 类别 | 含义 | 该怎么做 |
| --- | --- | --- |
| `A 游戏有 / 零协无此文件` | 零协压根没建这个文件 | **全译**（用 `--add-missing` 建骨架） |
| `A0 游戏有 / 零协是空占位` | 零协建了文件但是 `{}` | **全译**，这是「游戏刚更新」的典型信号 |
| `B 零协有但未译完` | en 记录数 > 零协记录数 | **只补差额** |
| 无缺口 | 零协已覆盖 | **不要自己译**，用了反而偏离零协 |

**逐条漏译清单**：`scope.py` 还会写出 `terms/_review/scope_untranslated.tsv`，
逐条列出零协漏了哪条记录、漏在哪个字段：

```
rel                             id                  why              fields
StoryData/S1002B.json           1023                零协缺此记录      content
RPGSystem/rpg-loc-location-*.json  130600            零协该字段为空    text
```

这是**真正的工作清单**——`B` 类文件里大部分记录零协已经译好，
要译的往往只有几条，照单译即可。

**把 A 类文件建进补丁**（结构照抄官方 en，文本暂留英文作待译标记）：
```
python3 tools/scope.py --add-missing
```
已存在的补丁文件**不会被覆盖**，可以放心重复跑。

**源语言标记**：报告每行末尾有 `源=KR(n)` 或 `源=EN(⚠无韩文)`。
带 `⚠无韩文` 的说明官方还没出韩文（常见于 `UserBanner-*`、`UserTicket-*` 这类配置），
此时**退而用英文**，并在译文里留意英文的七类固有错误（见 `重译手册.md §0.6`）。

### 第 4 步：译（按文件类型选工具与翻译单位）

| 文件类型 | 工具 | 翻译单位 | 上下文来源 |
| --- | --- | --- | --- |
| `StoryData/*.json` | `tools/ctx_dump.py` | 对话回合 | 说话人序列 + 相邻条目 |
| `RPGSystem/rpg-loc-dialogue-*.json` | `tools/rpg_dump.py` | **一组（key）** | 组内一问一答 |
| `RPGSystem/rpg-loc-item/npc/quest/location/*.json` | `tools/rpg_dump.py` | 单条（字段独立） | 同文件其他条目保持一致 |
| 机制 / UI / 技能 / 被动 | 直接读 + `terms/` | 单条 | 模板化，套 `style/机制句式模板.md` |

**每译完一个文件就自检**，不要攒着：
```
python3 tools/verify_retrans.py <文件>                  # 必须 错误 0
python3 tools/check_speech_context.py --files <文件>    # 口吻 0 告警
```

### 第 5 步：两轮审校（本次总结出的节奏）
1. **第一轮 带上下文重译**：修**语义错误**（回应关系、比喻、反讽、指代、漏译、半句跨条）
2. **第二轮 通读润色**：修**读不顺**（跟英文被撑长、漏信息、生硬句式）

第二轮不要与第一轮合并——先保证「意思对」，再保证「读得顺」。
**第二轮务必先读 `通读润色手册.md`**，否则会按个人偏好把零协的正式文风磨平。

### 第 6 步：跨文件术语统一（必做，最容易漏）
新批次必然引入新术语，收尾时必须做一次全局扫描：

```
cd /home/shb/文档/汉化
for w in 外来者 异邦人 经理老爷 经理阁下 友方单位 同伴 金枝 黄金枝 改衣师 裁缝师; do
  printf "  %-10s %s\n" "$w" "$(grep -rho "$w" _kb/patch_v2/ | wc -l)"
done
```

**判据**：查零协语料里哪个写法是主流，用主流的那个：
```
# 零协目录名带版本号，先取版本号最大的那个：
BASE=$(ls -d LimbusLocalize_latest* | sort | tail -1)
grep -rho <词> "$BASE/LimbusCompany_Data/Lang/LLC_zh-CN/" | wc -l
```
本会话就是这样定案了 13 处偏离（`异邦人→外来者`、`管理人到经理`、`经理阁下→经理老爷`、
`征收人/员→征收人员`、`裁缝师/修改师→改衣师`、`暗影→影界`、`两件套→西装组`、
`迪布瓦→杜布瓦`、`同伴(아군)→友方单位`、`影院→放映室` 等）。

### ⚠️ 第 8 步：别忘的三件事
