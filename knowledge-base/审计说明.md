## 1. 审计对象与判定标准

**对象**：《Limbus Company》第十章等新增内容的个人 AI 汉化补丁
（`_kb/patch_v2/`，129 个文件）及其配套流程与知识库。

**这套产出的定位**：补丁是**上游零协汉化的缺口补充包**，不是替代品。

**判定标准（按优先级）**——这是项目的核心规则，请以它为准绳：

| 维度 | 以谁为准 | 含义 |
| --- | --- | --- |
| **文风** | 都市零协会汉化（下称「零协」） | 句长节奏、书面／口语度、敬语与自称、标点习惯、专有格式 |
| **术语** | **零协** | 专名、状态名、技能句式、机制用语、品牌名 |
| **语义** | **官方韩文原文** | 到底说了什么：信息量、指代、否定、程度、因果、说话人 |

一句话：**用零协的词，说韩文的话。**
依据见 `_kb/workflow/重译手册.md §0.6`（韩 > 英）与 `§0.6b`（中文侧裁决）。

**为什么语义不跟零协**：零协自己也会压缩改写。已实测两处零协丢信息
（`S1002B#2` 丢「从罗佳口中」、`S1005B#3` 丢「赫尔曼那帮蠢货」）。
**所以「与零协逐字相同」不等于「语义正确」，这是本次审计最需要独立判断的点。**

**明确的非目标**（不在审计范围内，不必花时间）：
- 不追求与零协逐字一致（只在文风与术语上对齐）
- 不做全量重译（只补零协的缺口）
- 不覆盖零协原文（见 §3 红线）

## 3. 看什么：六条审计线

### 线 1 ⭐ 红线：补丁有没有改写零协已有原文

**要求**：补丁**绝不能**改动零协基础包里已有的非空原文。
（零协留空或缺失处由补丁补齐，是允许的，那是补丁存在的意义。）

```bash
cd /home/shb/文档/汉化/_kb
python3 tools/verify_retrans.py --all
```
**通过标志**：末尾出现 `✅ 红线：未改写零协任何已有原文`。
**当前值**：129 文件 / 错误 0 / 警告 0 / 红线 0 处。

> 请独立验证这条：自己写一个比对脚本，或用 `git log` 查补丁历史里有没有「零协译文被覆盖」的提交。
> 该检查已内置自测（见 `tools/verify_retrans.py` 的 `redline_check()`），但**内置检查本身也应被审计**。

### 线 2 ⭐ 语义忠实度（**最需要人工判断的一条**）

**要求**：每句译文相对韩文原文**不丢信息、不加戏**。

**取证方法**：随机抽样，对着韩文读。语料是现成的：
```bash
python3 tools/pm_lib.py show <文件关键字>     # 四语逐条对照
python3 tools/ctx_dump.py StoryData/S1004B.json --out /tmp/x.txt   # 带上下文与说话人
python3 tools/rpg_dump.py RPGSystem/rpg-loc-dialogue-floor-1.json --out /tmp/x.txt
```
**已知的高风险模式**（文档 `workflow/与零协差距教材.md` 自陈的「三大病」）：
1. **叙事爱加戏** —— 加了原文没有的意象、比喻、心理补白
2. **对话缩过头** —— 丢句尾语气助词、丢敬称
3. **破折号滥用** —— 实测我 23.7/千条 vs 零协 0.48/千条（约 50 倍）

**⚠️ 请重点检验这个方法论问题**：
`tools/sem_check.py` 是机械筛子，但它**测不出「句子通顺但少说了内容」**——
对两个已知真问题（`S1002B#2`、`S1005B#3`）都给 0 分。
**如果审计结论是「语义无法靠现有工具保证」，那是一个正确且有价值的结论。**

### 线 3 术语一致性

**要求**：术语与零协一致。

**取证**：
```bash
# ① 现成对照表（同现实证配对，最高置信）
head -20 terms/confirmed_pairs.tsv
# ② 直接在零协语料里查主流写法
BASE="$(ls -d ../LimbusLocalize_latest* | sort | tail -1)/LimbusCompany_Data/Lang/LLC_zh-CN"
grep -rho '黑派[^"，。！？、）)]\{0,6\}' "$BASE" | sort | uniq -c | sort -rn | head
```
**⚠️ `tools/check_established_terms.py` 不是守门器**：它在一批**与零协逐字相同**的文件上
仍报 85 条「不一致」，逐条核实后 **85/85 全是误报**（例：从 `Heads Hit` 学出术语 `Head`→「头部」）。
它的输出只能当线索。

### 线 4 结构安全（会不会让游戏崩）

**要求**：JSON 合法、字段集合与官方一致、引擎标签逐字符保留。

```bash
python3 tools/verify_retrans.py --all    # 含键序列/标签/占位符/空译检查
python3 tools/doctor.py                  # 环境与安装一致性
```
**已记录的教训**：JSON 合法 **≠** 游戏能读。曾因记录字段集合与官方不一致而闪退。
相关排查见 `workflow/更新与排障.md §2`（闪退优先级表）与 `§3`（二分定位法）。

### 线 5 流程可复现性

**要求**：流程能照文档跑通，且**结论可复现**。

```bash
python3 tools/doctor.py       # 体检
python3 tools/scope.py        # 算「新内容在哪、零协漏了什么」
```
**⚠️ 请重点审计这一条**：本项目历史上多次出现**工具报「0 问题」而实际什么都没查**（假通过），
详见 §7。**请对每个「0」问一句：这个工具真的能报出问题吗？**

### 线 6 交付一致性

**要求**：`_kb/patch_v2/`（真源）、游戏安装目录、仓库 `patch/`、发布包**四者一致**。
```bash
cd /home/shb/文档/汉化
LANG=C diff -rq _kb/patch_v2 Limbus-zh-CN-patch/patch | wc -l          # 应为 0
LANG=C diff -rq _kb/patch_v2 "$HOME/.local/share/Steam/steamapps/common/Limbus Company/LimbusCompany_Data/Lang/LLC_zh-CN" | grep -vc '^Only in'   # 应为 0
```

## 6. 项目自陈的关键规则（请检验是否真被遵守）

1. **一行原文 → 一行译文**：不加意象、比喻、心理补白
   （反面案例：`S1004B#166` 曾自造「他本可以选择说出来；也有愿意倾听的耳朵，但他始终没有。」）
2. **保留句尾语气助词与敬称**（`吧/呢/吗/哦`；`그분`→「那位大人」）
3. **引擎方括号标记原样保留**（`[OnSucceedAttack]`），显示方括号要译（`[鸿璐]`）
4. **富文本标签逐字符不变**（`<color=…>`、`<size=…>`、`<style=…>`、`{0}`）
5. **良秀的缩写一律「汉字·汉字」点分**，不用拉丁
6. **`id: null` 的记录不能用位置写回**（`S1004B`/`S1005B` 会错位）
7. **改必须改在 `_kb/patch_v2/`**（否则下次与零协合并时被覆盖）

## 7. ⚠️ 已知弱点（项目自陈，请优先证伪）

**本项目最大的流程风险：工具报「0 问题」而实际什么都没查。** 已发生 4 次：

| 假通过 | 真相 | 现状 |
| --- | --- | --- |
| `check_established_terms.py` 报「不一致 0」 | 用相对路径，从 `_kb` 运行会比对空集合 | 已改绝对路径 + 加存在性断言；但**其 85 条输出仍全为误报** |
| `verify_retrans.py --all` 报「错误 0（**0 个文件**）」 | patch 目录名不对，一个文件都没检查 | 已加硬断言：目标为空即退出码 2 |
| `scope.py` 报「没有缺口」 | 判据只比**记录数**，测不出「组内少一条对话」 | 已改为递归可译文本条数；因此多抓出 3 个文件 / 约 130 条真实漏译 |
| `check_speech_context.py` | 曾硬编码指向一份**已被清理**的旧零协包 | 已改自动选包 + 加断言 |
| 手写红线脚本报「改动 0 处」 | 把「补丁缺字段」误当改写 | 已固化进 `verify_retrans.py` 并加双向自测 |

**由此产生的审计建议**：
> **对任何「0 问题」的结论，先用一个已知的坏样本验证该工具真的能把它报出来。**
> 否则那个「0」可能只是工具坏了。

**其他已自陈的弱点**：
- `sem_check.py` 测不出语义丢信息（§3 线 2）
- 134 条零协漏译**没有上游中文可比对**，只能靠韩文
- 9 个文件**官方无韩文**，只能以英文为源
- 语义复核目前**没有自动化手段**，依赖人工对韩文精读
